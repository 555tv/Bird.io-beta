# Bird Game — минимальный мультиплеер-сервер

Что это делает: сервер на Node.js держит список подключённых игроков и в
реальном времени (через WebSocket/socket.io) рассылает всем позицию, HP,
вид (species) и угол поворота каждого игрока. Клиент (браузер) по-прежнему
сам считает свою физику — сервер только делает игроков видимыми друг другу.

## Структура проекта

```
bird-game-server/
├── server.js        ← Node.js сервер (express + socket.io)
├── package.json      ← зависимости
├── public/
│   └── index.html    ← сама игра (клиент), уже подключена к socket.io
└── README.md
```

## Запуск локально

Нужен установленный Node.js (18+). Затем:

```bash
cd bird-game-server
npm install
npm start
```

Сервер поднимется на `http://localhost:3000`. Открой этот адрес в браузере —
это и есть игра. Открой его же во второй вкладке (или дай ссылку другу в
локальной сети через свой IP, например `http://192.168.1.23:3000`) — вы оба
увидите друг друга в одном мире, двигающимися в реальном времени.

## Что уже работает

- Позиция, HP, вид, угол поворота и статус полёта каждого игрока
  синхронизируются ~8 раз в секунду.
- Чат работает через сервер (сообщения приходят всем мгновенно).
- При отключении игрока (закрыл вкладку) он сразу пропадает у всех.

## Что осознанно НЕ реализовано (это следующий шаг)

Это **минимальная** версия, чтобы просто увидеть друг друга в одном мире.
Сервер не проверяет и не считает:

- поедание еды/добычи другими игроками;
- урон между игроками при столкновении;
- эволюцию/уровни.

Это по-прежнему считается локально в браузере каждого игрока — то есть в
данный момент теоретически можно читерить через консоль браузера (менять
свой HP, счёт и т.д. напрямую в JS). Для честной игры со многими людьми
логику поедания/урона/эволюции нужно перенести на сервер, чтобы именно он
решал, что произошло, а не клиент. Это отдельная, более объёмная задача —
скажи, если понадобится, сделаем.

## Как выложить в интернет (чтобы играть не только в локальной сети)

Статический хостинг (Netlify, GitHub Pages) здесь **не подойдёт** — им
нужен постоянно работающий процесс с WebSocket. Нужен хостинг, который
держит Node.js-процесс:

- **Render.com** (есть бесплатный тариф): New → Web Service → подключить
  репозиторий (или загрузить папку) → Build Command: `npm install`,
  Start Command: `npm start`.
- **Railway.app** — похожий процесс, тоже есть бесплатный лимит.
- **Fly.io** — чуть более гибкий, требует `flyctl`.
- Свой VPS (DigitalOcean, Timeweb и т.п.) — устанавливаешь Node.js,
  запускаешь `npm start` через `pm2` или `systemd`, чтобы сервер жил
  постоянно и перезапускался при падении.

После деплоя просто открой выданный сервисом адрес (например
`https://your-app.onrender.com`) — там будет сразу и игра, и сервер вместе,
делить их отдельно не нужно.
